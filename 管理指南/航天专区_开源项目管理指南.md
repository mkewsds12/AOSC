# 航天专区 · 开源项目管理指南

> 适用后台：GitLink 特色专区「航天开源社区」管理后台 → 项目管理
> 维护对象：项目配置 / 项目分类 / 项目列表
> 整理时间：2026-08-10
> 关联文档：《航天专区_资讯维护指南.md》（资讯板块）、《开源项目调研.md》（项目来源池）

---

## 一、后台入口与整体结构

1. 登录 GitLink 账号（需专区管理员权限）
2. 进入特色专区 → 航天开源社区 → 管理后台 → **项目管理**
   - 项目配置：专区项目板块的全局设置
   - 项目分类：先建分类，再往分类里挂项目（核心）
   - 项目列表：管理已添加的项目（编辑/删除/排序）
3. 前台对应页面：/zone/space/projects
   - 左侧：分类筛选（全部分类 + 各分类）
   - 主体：项目卡片列表（Logo、标题、描述、语言标签、点赞/收藏数、分类、更新时间）

> 维护顺序建议：**先建分类 → 再添加项目并归入分类**。

## 二、项目分类管理（怎么划分类）

### 2.1 推荐分类划分

项目分类直接决定前台左侧筛选栏，采用**航天分系统标准 9 类**（姿控/测控/星务均为行业通用术语）+ **2 个补充类**（整星与仿真有明确落点），前期建议先建 **9 个核心分类**：

| 序号 | 分类名称 | 定位 | 示例项目 |
|------|---------|------|---------|
| 1 | 操作系统 | 星载 OS、实时系统、虚拟化容器 | Zephyr、RTEMS、Space Grade Linux、KubOS |
| 2 | 测控通信 | 遥测遥控、链路协议、CCSDS | libcsp、gr-satellites、SatNOGS COMMS |
| 3 | 姿控算法 | 姿态确定与控制、星敏感器 | OpenStarTracker、Basilisk |
| 4 | 星务处理 | 星务计算机、飞控框架、指令调度 | cFS、F Prime、NanoSat MO、sat-rs |
| 5 | 数据管理 | 遥测数据、上注、下行、存储 | Serial Studio、CCSDSPy |
| 6 | 算法处理 | 在轨 AI、遥感算法、压缩编码 | KENSAT、PhiSat-2 生态、JAXA open-set |
| 7 | 任务规划 | 任务调度、星座规划 | SatelliteRL、Constellation-Design-MILP |
| 8 | 应用服务 | 载荷服务、SataaS、应用 | satpy、noaa-apt、Space Cloud |
| 9 | 地面测试 | 地面站、测运控、测试验证 | SatNOGS、Yamcs、OpenC3、SatDump |

补充类（建议也建，否则整星/仿真项目无落点）：

| 序号 | 分类名称 | 定位 | 示例项目 |
|------|---------|------|---------|
| 10 | 整星参考设计 | 完整开源卫星/立方星整星项目 | UPSat、KS-1Q、DelfiSpace、OreSat |
| 11 | 仿真与轨道力学 | 轨道传播、任务分析、仿真 | 42、GMAT、Orekit、poliastro |

> 可后续扩展：**开源硬件**、**论文与资料**（有内容再开）。

### 2.2 分类命名建议

- 名称简短（2-6 字），与前台筛选栏展示匹配
- 9 类对应航天行业分系统惯例，社区成员容易对号入座
- 与专区定位一致：围绕小卫星 / 立方星 / 智能星 / 星上计算 / 星上智能体 / 测运控
- 分类一旦有项目归属后不要轻易改名/删除（删除前需先清空或迁移该分类下项目）

### 2.3 分类首图

- 后台支持为分类设置展示信息，建议每个分类给一句定位说明，便于前台理解
- 有代表性 banner 图可配，没有可先不配

## 三、添加 / 管理项目

### 3.1 添加项目流程

1. 进入"项目管理 → 项目列表"→ 点击**添加项目**
2. 在平台内**搜索项目**（按项目名称/所属组织检索，如搜 sds3、UPSat 等）
3. 选中目标项目 → 指定所属分类 → 保存
4. 前台即显示在对应分类下

> 注意：专区挂的是**平台内已有项目**，项目本体仍在原组织/仓库；如需展示外部项目（GitHub/GitLab），需先在 GitLink 上创建镜像仓库或收录（见第五节）。

### 3.2 项目卡片字段说明（前台展示）

| 字段 | 说明 |
|------|------|
| Logo | 项目仓库自带图标，自动展示 |
| 标题 | 组织名/项目名（如 SDS³ - ... / sds3_semx） |
| 描述 | 项目简介（来自仓库 README 简介，管理时可补充） |
| 语言标签 | 仓库主要语言（Python/C/Verilog 等） |
| 点赞/收藏数 | 平台统计，自动更新 |
| 分类 | 所属分类（前台可筛选） |
| 更新时间 | 最近更新，自动记录 |

### 3.3 项目描述规范

- 描述保持 1-2 句，突出"是什么 + 干什么用 + 技术栈亮点"
- 自有项目（sds3_*）建议按统一格式写：`面向 XX 的 XX 能力，提供 XX 功能（语言/平台）`
- 收录项目注明来源性质（如"整星参考""镜像收录"），便于区分自研与收录

## 五、前台展示与维护规范

### 5.1 前台结构

- 前台"开源项目"页左侧为分类筛选（全部分类 + 各分类），主体为项目卡片
- 分类建好后前台自动出现筛选项；分类下无项目时显示为空，建议**每个分类至少挂 2-3 个项目**再开放
- 首页"精选项目"区展示重点推荐项目，优先放：自有项目 + 整星参考（UPSat/KS-1Q）

### 5.2 收录 / 维护规范

- **来源区分**：自有项目直接挂；外部项目（GitHub/GitLab/Gitee）需先在 GitLink 建立镜像仓库或收录后再挂
- **来源标注**：收录项目在描述中注明来源链接、License、镜像同步策略、维护人（参考《SDS3_GitLink_组织管理与仓库调研.md》7.3 节）
- **整星拆解**：整星项目整体挂在"整星参考设计"，高价值子模块（OBC/EPS/ADCS/COMMS）拆出挂到对应分类（如 UPSat 的 OBC → 星载系统与飞控）
- **版权红线**：只挂开源许可的项目；涉密/未开源的不挂

### 5.3 更新频率

- 新收录项目随调研进度持续补充（建议每 1-2 周挂 1 批）
- 自有项目（sds3_*）随发布节奏更新
- 定期清理：长期无维护且无价值的项目可移除，保持分类整洁

## 六、常见问题

| 问题 | 处理 |
|------|------|
| 找不到"添加项目" | 确认管理员权限，在"项目列表"页右上角 |
| 搜不到想挂的外部项目 | 该项目可能不在 GitLink 平台，需先创建镜像仓库或提交收录申请 |
| 分类删不掉 | 分类下有项目时通常需先清空/迁移项目 |
| 前台分类显示空 | 该分类下还没挂项目，先添加项目 |
| 项目描述太长 | 平台一般截断显示，控制 1-2 句 |
| 如何区分自研与收录 | 描述中统一加"收录自：来源"或"镜像"字样 |
