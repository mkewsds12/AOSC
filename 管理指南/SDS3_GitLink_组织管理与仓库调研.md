# SDS³（GitLink）组织管理与仓库调研笔记

> 整理时间：2026-08-10
> 信息来源：gitlink.org.cn/sds3 组织页面、SDS3_UploadFileManager 仓库页面、组织页面截图

## 一、平台概况

- **GitLink**（gitlink.org.cn）：开放原子开源基金会旗下的开源代码托管平台，功能体系与 Gitee/GitHub 类似
- **SDS³ - Software Defined Satellite Service Stack**（软件定义卫星服务栈）
- 愿景：在 Linux 与成熟开源生态基础上，构建面向星载计算的标准化开源软件框架，提供**数据管理、在轨维护、任务管理、虚拟化、容器化、分布式计算与容错**等通用化解决方案，推动"卫星即服务"（SataaS）落地
- 组织成员 3 人：jonah_liu、akok、phylis7
- 组织团队 2 个：麦芽卫星实验室（3 人 / 12 仓库）、SDS3 Open Group（0 人 / 12 仓库）

## 二、组织管理需要的操作

1. **创建/加入组织**：注册账号后在"组织"页新建组织或接受邀请
2. **成员管理**：邀请成员（邮箱/账号）、设置成员角色、移除成员
3. **组织设置**：组织名称、Logo、可见性（公开/私有）、默认仓库权限
4. **仓库管理**：组织下创建仓库、转移/删除仓库、设置仓库成员权限
5. **团队管理**：按团队划分人员和权限
6. **审计与令牌**：查看操作日志、管理组织 Access Token

## 三、文件上传需要的操作

1. **网页直接上传**：仓库页面 → 上传文件，拖拽或选择本地文件提交
2. **Git 方式**：`git push`（日常最常用，需配置 SSH key 或 HTTPS 凭据）
3. **发布物上传**：仓库 Releases/发行版上传压缩包、安装包等附件
4. **文档/Wiki 上传**：文档中上传图片、附件
5. **Issue 附件**：反馈问题时可附带图片/文件

## 四、需要的权限（核心）

| 层级 | 角色 | 权限 |
|------|------|------|
| 组织级 | Owner（所有者） | 全部权限，含组织管理 |
| 组织级 | Admin（管理员） | 组织管理（邀请成员、改设置） |
| 组织级 | Member（成员） | 常规协作 |
| 仓库级 | Maintainer（维护者） | Release 发布、分支保护等 |
| 仓库级 | Developer（开发者） | 网页上传文件 / git push（写权限） |
| 仓库级 | Reporter/Guest（只读） | 查看和下载，不能上传 |

**结论**：要做"组织管理 + 文件上传"，需要组织 Owner/Admin 角色，同时仓库内至少 Developer 写权限。大文件（>100MB）不适合直接 push，建议走 Releases 附件或 LFS。

## 五、仓库目录划分现状

### 组织层面：多仓库架构（一组件一仓库）

SDS³ 明确采用 **polyrepo** 架构，官方说明"均按独立组件仓库维护"——每个功能组件单独一个仓库，覆盖平台管理、星地交互、任务调度、数据管道、载荷服务全生命周期。目前共 **12 个仓库**，例如：

- SDS3_UploadFileManager（上注文件管理）
- SDS3_BuildDownloadFile（遥测/下行数据管理）
- sds3_bmc_firmware（BMC 固件，STM32F105RC）
- sds3_ttc（测控链路抽象与任务指令转发）
- SDS3_cameras 等

组织页面**仓库列表没有分类目录**，只有"组织团队"做归属划分（麦芽卫星实验室 / SDS3 Open Group），且团队是人员维度而非仓库分类。

### 仓库内部：有标准目录划分

以 SDS3_UploadFileManager 为例：

```
UploadFileManager/
├── readme.md      # 说明文档
├── src/           # 源码
├── systemd/       # 服务启动管理
└── makeDebPKG/    # Debian 安装包制作
```

语言构成：C++ / shell / C。各组件仓库基本按 `src + systemd + 打包脚本 + 文档` 的固定套路组织，readme 统一说明"代码结构 / 程序输入 / 程序输出 / 文件部署目录 / Debian 安装包"。

### 两个注意点

- 仓库标注"同步镜像"，从 `gitee.com/maiar-lab` 镜像同步，改动需注意双向同步策略
- 官方注明"仓库名称与边界可能按社区共识持续调整"，组件划分尚未完全定型

## 六、顶层设计与领域划分（建议方案）

### 6.1 对现有 9 类划分的评价

**总体合理，可以直接作为基础**：9 类对应航天行业经典分系统划分（姿控 ADCS、测控 TTC、星务 CDH、地面 GSE 均为业内通用术语），社区成员容易对号入座，命名前缀也规范。

**建议补充 5 类**，主要缺口：

| 缺口 | 原因 |
|------|------|
| 虚拟化与容器化 | SDS³ 愿景核心（虚拟化、容器化、分布式计算、容错）目前无处安放，只能硬塞进"操作系统" |
| 仿真与数字孪生 | 数学仿真/HIL/星座仿真在开源社区非常活跃（如 42 姿轨模拟器、Orekit），与"地面测试"不是一回事 |
| 参考整星与演示 | FOSSASAT-1、UPSat、OreSat 这类**整星项目**横跨多个分系统，塞进任何单一领域都牵强 |
| 知识资产 | 论文、书籍、教程、数据集、标准是明确要收录的内容，9 类全是"软件功能"维度，放不下 |
| 社区基建（可选） | 模板、CI/CD、组织规范需要统一落点 |

**两个边界问题**：
- "算法处理"范围过宽：建议明确为**在轨 AI / 遥感处理 / 压缩编码**，与"姿控算法""任务规划"划清边界
- "测控通信"可容纳星间链路/组网（星座场景），暂不单列

### 6.2 顶层设计思路：领域为主 + 来源为辅 + 标签补充

```
维度一（主）  技术领域        → 仓库命名前缀，决定"放哪"
维度二（辅）  资产来源        → 组织团队 + 前缀区分（自研/社区收录/知识资产），决定"谁维护"
维度三（标签）卫星类型        → 小卫星/立方星/智能星/智能星座，README 与 Wiki 标注，不占命名
```

### 6.3 推荐分类表（原 9 类 + 新增 5 类 = 14 类）

| 层级 | 领域分类 | 前缀 | 覆盖内容 | 状态 |
|------|---------|------|---------|------|
| 基础平台 | 操作系统 | sds3-os- | 星载 RTOS/Linux、内核裁剪、BSP、驱动 | 原有 |
| 基础平台 | 虚拟化与容器化 | sds3-virt- | 容器运行时、虚拟化、容错、分布式计算 | **新增** |
| 星务平台 | 星务处理 | sds3-cdh- | 星务计算机、综合电子、指令调度、健康管理 | 原有 |
| 星务平台 | 数据管理 | sds3-dm- | 遥测数据、上注、下行、文件存储 | 原有 |
| 测控通信 | 测控通信 | sds3-ttc- | 遥测遥控、射频链路、调制解调、协议（含星间链路） | 原有 |
| 姿轨控 | 姿控算法 | sds3-adcs- | 姿态确定、姿态控制、星敏感器（含轨道导航） | 原有 |
| 任务应用 | 任务规划 | sds3-plan- | 任务规划、自主调度、冲突消解 | 原有 |
| 任务应用 | 算法处理 | sds3-alg- | 在轨 AI、遥感处理、压缩编码 | 原有 |
| 任务应用 | 应用服务 | sds3-app- | 载荷服务、SataaS、星上智能体应用 | 原有 |
| 地面支撑 | 地面测试 | sds3-gse- | 地面站、测试工具、检飞、运维 | 原有 |
| 地面支撑 | 仿真与数字孪生 | sds3-sim- | 数学仿真、HIL、星座仿真 | **新增** |
| 知识资产 | 参考整星与演示 | sds3-ref- | 整星开源项目整体收录、参考设计 | **新增** |
| 知识资产 | 论文与书籍 | sds3-doc- | 论文、书、教程、数据集、标准 | **新增** |
| 社区基建 | 社区工具 | sds3-meta- | 模板、CI/CD、文档站点、组织规范 | **新增** |

> 起步建议：先按**原 9 类** + `sds3-virt-` + `sds3-ref-` + `sds3-doc-`（共 12 类）落地，`sim`/`meta` 视内容量再开。

### 6.4 命名规范（一仓库一领域）

```
sds3-<领域>-<组件名>           自研，如 sds3-dm-upload-file-manager
sds3-x-<领域>-<组件名>         社区收录（x = eXternal），如 sds3-x-adcs-open-star-tracker
sds3-doc-<类别>-<名称>         论文/书/教程，如 sds3-doc-paper-constellation-scheduling
```

### 6.6 落地方式（GitLink 平台不支持仓库自定义分类目录）

1. **命名前缀规范**：仓库名带领域前缀，列表按名称即可归类（核心手段）
2. **组织首页"仓库地图"**：README 放分类索引表，全部仓库映射到 14 类，附领域说明
3. **Wiki 分层目录**：按 14 类建 Wiki 页面，每页列所属仓库 + 收录项目清单 + 相关论文
4. **组织团队改造**：两个团队改为来源维度——"麦芽卫星实验室"= 自研维护，"SDS3 Open Group"= 社区收录/协作（与现状吻合，无需大改）
5. **标签补充**：README 头部统一标注卫星类型标签（小卫星/立方星/智能星/智能星座），方便筛选

## 七、收录范围与来源策略

### 7.1 收录范围

| 内容 | 来源 | 落点 |
|------|------|------|
| 自研代码 | 麦芽卫星实验室 | sds3-<领域>-* |
| 社区开源项目（小卫星/立方星/智能星/智能星座/星上计算/星上智能体） | 镜像/收录 | sds3-x-<领域>-* |
| 开源论文、书、教程 | 资料收集 | sds3-doc-* |

### 7.2 首批收录建议（撑排面）

1. **UPSat** 全套软硬件图纸与代码（最完整的开源卫星）→ sds3-ref- + 分系统拆解
2. **SatNOGS**（地面站网络）→ sds3-gse-，社区活跃、影响力大
3. **OpenStarTracker + nova.astrometry.net**（星敏感器闭环）→ sds3-adcs-
4. **42 模拟器** → sds3-sim-
5. **FOSSASAT-1** → sds3-ref-（话题性最强）

### 7.3 收录来源标注规范

每个收录仓库 README 固定段落：`来源链接 / 原项目 License / 镜像同步策略 / 维护人`，防止版权与同步问题（注意现有仓库"同步镜像"标注，双向同步需明确策略）。
