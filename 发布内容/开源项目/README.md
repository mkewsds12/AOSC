# 开源项目 · 发布内容目录说明（README）

> 本目录用于组织「开源项目」板块的**项目收录工作**，与 GitLink 专区后台「项目管理」对应
> 配套文档：《管理指南/航天专区_开源项目管理指南.md》、《项目管理/README.md》
> 整理时间：2026-08-10（已按「来源组织」重构）

---

## 一、本目录定位

`发布内容/开源项目/` 存放社区收录国外/国内开源航天项目的**全部建档材料**。

收录思路：**按「来源组织（owner）」建档**，而非按领域分类建文件夹。每个来源组织一个文件夹，内含该组织旗下项目的镜像导入指南与许可证核查结论。

> 领域分类（11 类）不再作为文件夹层级，而是标注在每个项目 md 的「项目类别」字段中，导入 GitLink 时直接选用。

## 三、每个组织文件夹里有什么

| 文件 | 用途 |
| :--- | :--- |
| `README.md` | 该组织的 GitLink 新建组织填写指南（账号/名称带"社区镜像"/描述/地区/头像）+ 仓库镜像清单 + 操作流程 + 合规备注 |
| `avatar.png` | 官方组织头像，建组织时上传（仅供辨识）；缺失的在 README 备注手动获取 |
| `<项目>.md` | 每个仓库一条：项目简介 + GitLink 导入表单逐字段填写指南（URL/拥有者/标识/简介/镜像勾选/类别/语言）+ 上架专区步骤 + 许可证核查结论 |

另有 `生态入口/` 文件夹：存放 topic 聚合页、在线服务官网、未公开项目等**非镜像**收录线索，不建镜像组织。

## 四、标准工作流（建组织 → 镜像 → 上架 → 分类）

每个组织的 README 已固化流程，整体为：

1. **建组织**：按组织 README 第一节在 GitLink 新建组织（账号 / 名称带"社区镜像" / 描述含非官方声明 / 上传 avatar.png）
2. **镜像导入**：组织内逐个「导入项目」，按项目 md 填表（URL 末尾带 .git、勾选镜像、保留 LICENSE）
3. **核对同步**：检查 README / LICENSE 是否同步正常
4. **挂专区**：专区后台 → 项目管理 → 添加项目 → 按项目 md 标注的「项目类别」上架
5. **宣传**：重要项目上新时在「新闻资讯/项目速递」发一篇（见《航天专区_资讯维护指南》）

**项目分类（11 类，上架时选用）**：操作系统 / 测控通信 / 姿控算法 / 星务处理 / 数据管理 / 算法处理 / 任务规划 / 应用服务 / 地面测试 / 整星设计 / 轨道仿真

## 五、许可证合规红线

- 组织名称与描述必须注明**非官方社区镜像**，不冒充官方
- 无 LICENSE = 无授权：只收官方链接，不镜像代码；确需镜像先取得维护者许可
- 镜像仓库只读、不修改上游、保留 LICENSE 与版权声明
- GitLab 重组 / 仓库 404 的组织，导入前先核对实际仓库路径

许可证总账与各组织状态（首批/第二批/仅收链接）见《项目管理/README.md》第五节。

---

## 六、维护说明

- 新增组织：调研确认 owner → 建档（README + avatar + 各项目 md）→ 按工作流执行
- 每个项目 md 标注**状态**（待发布/已发布），导入上架后手动更新为已发布
- 源仓库地址/许可证变更时，同步更新对应项目 md
- 自有项目（SDS³ 系列）不在此目录建档，直接在 GitLink 自有组织下维护
