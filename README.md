> 仓库：github.com/mkewsds12/AOSC
> 社区站点：[航天开源社区](https://www.gitlink.org.cn/zone/space)（GitLink 特色专区）

## 一、这是什么

本仓库是「航天开源社区」（Aerospace Open Source Community，简称 AOSC）的**维护工作仓库**，存放社区日常维护所需的全部文档、分类体系、待发布内容与调研成果。

社区前台运行在 GitLink 特色专区（/zone/space），包含三大板块：

| 板块 | 后台入口 | 内容 |
| :--- | :--- | :--- |
| 开源项目 | 管理后台 → 项目管理 | 展示收录的开源项目（按 11 个分类） |
| 资源发布 | 管理后台 → 资源管理 | 标准、资料、安装包、数据集、技术报告 |
| 新闻资讯 | 管理后台 → 资讯管理 | 专区动态、项目速递、技术前沿、行业新闻、活动通知 |

## 三、日常维护总流程（核心）

社区维护遵循固定流水线，**建组织 → 搬运 → 添加 → 分类**，按序执行：

### 第 1 步：建立组织（先有"家"，再收录）

在 GitLink 上为社区建立**组织/账号**，作为所有收录项目的"挂靠主体"：

1. 在 GitLink 注册并创建组织（如 sds3 / 太湖星云相关组织）
2. 组织信息按统一模板填写（组织主体一句话 + 核心方向 + 合作方 + 固定结尾声明"以收录与镜像方式展示，版权归原始组织"）
3. 自有项目（SDS³ 系列）直接建在组织下；收录项目挂靠到该组织名下但注明原始归属

> 关键原则：**社区组织 ≠ 项目原始组织**。收录/镜像项目不冒充自有，简介中必须注明原始组织、官方仓库与许可证。

### 第 2 步：搬运项目（让项目进入 GitLink）

把选定项目导入 GitLink（两种方式）：

- **自有项目**：直接在 GitLink 组织下新建仓库并上传代码
- **外部项目**（GitHub/GitLab）：使用后台「导入项目」功能，填写：
  - 导入仓库URL：`https://github.com/<org>/<repo>.git`（必须带 .git）
  - 拥有者 / 项目名称 / 项目标识（英文关键字）
  - 项目简介（≤200 字："是什么 + 干什么 + 技术栈"，末尾注明"社区镜像，原始组织：XXX"）
  - 勾选「该仓库将是一个镜像」（只读，每 8 小时自动同步）
  - 项目类别 / 项目语言

**搬运合规检查**（导入前必查）：

- 必须有明确开源许可证（MIT/BSD/Apache/GPL 等）
- NOASSERTION / 无 LICENSE 的仓库：只做链接收录，不复制代码
- GPL 系项目：镜像保持同一许可证，不混入其他许可代码
- 许可证不明确 → 不放代码，仅在卡片放原始链接

### 第 3 步：社区中添加项目（挂到专区）

项目进入 GitLink 后，在专区后台挂载：

1. 进入 管理后台 → 项目管理 → 项目列表 → 添加项目
2. 在平台内搜索该项目（按名称/组织检索）
3. 选中项目 → 指定所属分类 → 保存
4. 前台即显示在对应分类下

> 注意：专区挂的是**平台内已有项目**；外部项目必须先完成第 2 步搬运，才能在专区添加。

### 第 4 步：项目分类（对号入座）

后台「项目分类」采用**航天分系统标准 11 类**：

| 序号 | 分类 | 定位 | 示例 |
| :--- | :--- | :--- | :--- |
| 1 | 操作系统 | 星载 OS、实时系统、虚拟化容器 | Zephyr、RTEMS、aerugo |
| 2 | 测控通信 | 遥测遥控、链路协议、CCSDS | libcsp、gr-satellites |
| 3 | 姿控算法 | 姿态确定与控制、星敏感器 | OpenStarTracker、Basilisk |
| 4 | 星务处理 | 星务计算机、飞控框架、指令调度 | cFS、F Prime、sat-rs、n7s-obcp |
| 5 | 数据管理 | 遥测数据、上注、下行、存储 | Serial Studio、asn1-pusc-lib |
| 6 | 算法处理 | 在轨 AI、遥感算法、压缩编码 | KENSAT、PhiSat-2、JAXA open-set |
| 7 | 任务规划 | 任务调度、星座规划 | SatelliteRL、MILP |
| 8 | 应用服务 | 载荷服务、SataaS、应用 | satpy、noaa-apt |
| 9 | 地面测试 | 地面站、测运控、测试验证 | SatNOGS、Yamcs、TASTE 工具链 |
| 10 | 整星设计 | 完整开源卫星/立方星整星项目 | UPSat、KS-1Q、DelfiSpace |
| 11 | 轨道仿真 | 轨道传播、任务分析、仿真 | 42、GMAT、Orekit |

## 四、三大板块日常维护

### 4.1 开源项目板块

- **来源池**：调研目录《开源项目调研.md》（300+ 项目）+ 各组织调研建议
- **收录优先级**：自有项目（SDS³）→ 国内合作组织 → 国外知名项目（镜像）
- **组织描述模板**：见各组织调研文件第二节（统一结尾声明）
- **维护节奏**：定期批量搬运 A 类项目（协议明确 + 定位契合），保持分类均衡

### 4.2 资源发布板块

按「文件格式（9 类）+ 内容领域（5 类）」双维度管理，详见《航天专区_资源发布指南.md》。

### 4.3 新闻资讯板块

5 个栏目（专区动态/项目速递/技术前沿/行业新闻/活动通知），草稿先放 `发布内容/新闻资讯/<栏目>/待发布/`，发布后移入 `已发布/`。行业新闻只搬运 1 周内动态并注明来源，详见《航天专区_资讯维护指南.md》。

## 五、待发布 → 已发布 工作流

每个分类/栏目子目录下均有 `待发布/` 与 `已发布/` 两个子目录：

1. 内容（项目/资源/新闻草稿）先放入 `待发布/`
2. 在 GitLink 后台完成发布/挂载后，将对应文件移入 `已发布/`
3. 已发布内容作为归档保留，便于追溯

## 七、维护约定

1. **先组织、后搬运、再添加、终分类**——流程不可跳步
2. 外部项目一律标注原始组织、官方仓库、许可证，明确"社区镜像"身份
3. 协议不明确的项目只收录链接，不搬运代码
4. 分类已定稿（11 类），有项目归属后不轻易改名/删除
5. 每个组织单独建调研文件，组织描述按统一模板
6. 发布内容先在 `待发布/` 再转 `已发布/`，保持目录整洁
