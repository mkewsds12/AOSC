# AOSC 卫星开源组织框架维护

本 skill 封装「航天开源社区」（Aerospace Open Source Community，AOSC）维护工作仓库的核心流程与规范，作为后续逐步固化的基础骨架。

- 本地仓库：`f:\个人\待办\卫星开源组织框架`（远程 `github.com/mkewsds12/AOSC`）
- 前台站点：GitLink 特色专区「航天开源社区」（`/zone/space`）
- 定位：面向小卫星、立方星、智能星与智能星座的开源协作平台，推动「卫星即服务」（SataaS）

## 二、核心维护流程（建组织 → 搬运 → 添加 → 分类）

### 1. 建立组织（先有「家」，再收录）

在 GitLink 为社区建立组织/账号，作为收录项目的「挂靠主体」。关键原则：**社区组织 ≠ 项目原始组织**，收录/镜像项目不冒充自有，简介必须注明原始组织、官方仓库与许可证。

### 2. 搬运项目（让项目进入 GitLink）

- 自有项目：直接在组织下新建仓库上传代码
- 外部项目：后台「导入项目」，填导入仓库 URL（`https://github.com/<org>/<repo>.git` 必须带 `.git`）、拥有者、项目名称、项目标识（英文关键字）、简介（≤200 字）、勾选「该仓库将是一个镜像」（只读，每 8 小时自动同步）、项目类别/语言

**搬运合规检查（导入前必查）**：

- 必须有明确开源许可证（MIT/BSD/Apache/GPL 等）
- NOASSERTION / 无 LICENSE 的仓库：只做链接收录，不复制代码
- GPL 系项目：镜像保持同一许可证，不混入其他许可代码
- 许可证不明确 → 不放代码，仅在卡片放原始链接

### 3. 专区添加项目（挂到专区）

管理后台 → 项目管理 → 项目列表 → 添加项目 → 搜索平台内项目 → 指定所属分类 → 保存。注意：专区挂的是平台内已有项目，外部项目必须先完成第 2 步搬运。

### 4. 项目分类（对号入座）

后台采用**航天分系统标准 11 类**：

| 序号 | 分类     | 定位                           |
| :--- | :------- | :----------------------------- |
| 1    | 操作系统 | 星载 OS、实时系统、虚拟化容器  |
| 2    | 测控通信 | 遥测遥控、链路协议、CCSDS      |
| 3    | 姿控算法 | 姿态确定与控制、星敏感器       |
| 4    | 星务处理 | 星务计算机、飞控框架、指令调度 |
| 5    | 数据管理 | 遥测数据、上注、下行、存储     |
| 6    | 算法处理 | 在轨 AI、遥感算法、压缩编码    |
| 7    | 任务规划 | 任务调度、星座规划             |
| 8    | 应用服务 | 载荷服务、SataaS、应用         |
| 9    | 地面测试 | 地面站、测运控、测试验证       |
| 10   | 整星设计 | 完整开源卫星/立方星整星项目    |
| 11   | 轨道仿真 | 轨道传播、任务分析、仿真       |

## 三、组织描述统一模板（用户定稿，必须遵守）

- 结构：① 组织主体一句话（国别/性质/成立时间）② 核心研发方向（2-3 个）③ 合作方/生态（如有）④ **固定结尾**
- 固定结尾：「本组织以收录与镜像方式展示 XXX 的开源项目，并明确标注原始组织、官方仓库与开源许可证；项目版权与维护权仍归 XXX 所有。」
- 固定结尾必须保留；描述精简为一段，不展开仓库数量/细节清单

示例（N7 Space）：N7 Space 是波兰一家专注航天软件与星载计算的工程公司，成立于 2018 年。公司围绕星载实时操作系统、安全关键软件、ECSS/CCSDS 标准实现与 TASTE 开发工具链开展研发，与欧洲航天局（ESA）保持深度合作。本组织以收录与镜像方式展示 N7 Space 的开源项目，并明确标注原始组织、官方仓库与开源许可证；项目版权与维护权仍归 N7 Space 所有。

## 五、Markdown 格式规范（批量整理 README 时）

- 表格分隔行用 `| :--- | :--- |`
- 裸 URL 用 `<url>` 包裹（MD060/MD034）
- 待发布组织 README 均含「状态流转」节；生态入口 README 是特殊目录，不加该节
- 处理含中文/全角括号的文本时，URL 正则字符集必须排除中文与全角括号，防止吞字
- CRLF 文件正则结尾用 `\r?$`；含中文的 PowerShell 脚本需 UTF8+BOM 保存

## 六、Git 协作要点

- `main` 是唯一权威分支，始终可发布；协作者不直接推送 main
- 任务在 `feature/<任务名>` 分支完成，通过 PR/合并请求合入 main
- 提交信息用中文描述性语句，按逻辑分多次提交
